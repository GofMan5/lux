# LUX TUI — мастер-план до зрелой библиотеки («как после 5 лет работы»)

> **Что это.** Единый план работ, после которого lux — лучшая библиотека для
> терминальных интерфейсов на Go и одна из лучших вообще. Не «ещё одна TUI»,
> а такая, на которой пишут серьёзные инструменты: git-клиенты, мониторинги,
> админки, редакторы, AI-агентов, SSH-приложения.
>
> **Как читать.** План разбит на части (I–XV). Внутри — фазы и пункты. У каждого
> пункта есть ID (например, `[RND-04]`), чтобы на него можно было ссылаться в
> коммитах и отчётах. Пункты с `- [ ]` ещё не сделаны, с `- [x]` — сделаны.
> Сессия, которая работает по плану, сама отмечает галочки.
>
> **Как выбирать следующую задачу.** Идти по «Годовому плану» (часть XIX):
> там сказано, какие ID в каком порядке. Внутри года — сверху вниз. Если
> задача упирается в другую — сначала сделать ту.
>
> **Язык.** План внутренний, поэтому по-русски. Всё, что видит пользователь
> библиотеки (README, godoc, docs/*.md кроме планов, сообщения об ошибках), —
> по-английски.

## Часть 0. Где мы сейчас — честная инвентаризация (октябрь 2026)

Это база. Её не переписываем, а развиваем. Если пункт плана уже частично
сделан — он помечен «доработка».

### 0.1. Рантайм (`lux`)

- Elm-цикл: `Model` с `Update(event) (Model, Command)` и `View(*Frame)`.
- Команды (`Command`) выполняются в горутинах, результат приходит событием;
  `Emit`, `Quit`.
- Анимации на абсолютном времени, адаптивный FPS (`WithMaxFPS`), гистерезис
  пейсера, пропуск устаревших кадров.
- В простое — ноль байт вывода и ноль кадров.
- Suspend/resume (Ctrl+Z, `WithSuspend`), восстановление терминала после
  паники в `Update`/`View`, после ошибки записи, после отмены контекста.
- Опции: `WithBackend`, `WithIO`, `WithMaxFPS`, `WithSizeLimit`,
  `WithFallbackSize`, `WithReducedMotion`, `WithKeyReleases`,
  `WithPixelMouse`, `WithHyperlinks`, `WithTitle`, `WithWidthPolicy`,
  `WithSuspend`, `WithProgress`, `WithNotifications`, `WithClipboard`.
- Метрики кадра (presented metrics, dropped frames), presentation hooks.
- Плоский (plain) бэкенд: один кадр в pipe/файл.

### 0.2. Рендер (`render`)

- Ячеечный буфер (`Buffer`, `DoubleBuffer`), `Cell` ≈ 80 байт.
- `Canvas`: `Subview`, `Clip`, `Fill`, `Put`, `PutMeasured`, `Text`,
  `TextWrap`, `Border`, каретка.
- Цвета: ANSI 16, 256, RGB. Атрибуты, подчёркивания разных стилей и цветов.
- OSC 8 ссылки.
- Ширины: графемы через uniseg, `WidthPolicy`, оверлей ширин, режим 2027.
- Перенос строк `WrapLines`/`MeasureWrap`.
- Диф буферов, `ScrollRows`, энкодер кратчайшей VT-последовательности.

### 0.3. Ввод (`event`, `internal/terminal`)

- Legacy VT, kitty keyboard (с release), win32-input-mode (с фиксом
  serialized-текста), мышь SGR и пиксельная (1016), bracketed paste, фокус.
- Пробинг возможностей терминала при старте (`capability`).

### 0.4. UI (`ui`)

- Immediate-mode `Context`: регионы, хит-тест, фокус, захват драга, модалки
  с ловушкой фокуса, пузырьки колеса, `FocusDelta`, `Shortcut` со скоупами.
- Виджеты: Button, Checkbox, RadioGroup, List, Modal, Gauge, ScrollViewport,
  Select, Shortcut, Sparkline, Spinner, Stepper (рецепт), Table, Tabs,
  TextArea, TextInput (оба с выделением, буфером обмена, undo/redo), Tree.
- Тема: 5 ролей (Text, Muted, Accent, Focus, Danger), по умолчанию только
  атрибуты, без цвета.

### 0.5. Прочие пакеты

- `layout`: `Flex` с ограничениями, `Classify` (размерные классы).
- `motion`: `Tween`, `Spring`, изинги (Linear, InOutCubic, OutCubic, OutBack).
- `scene3d`: софтверный 3D (меши, камера, свет) в ячейки.
- `capability`: снимок возможностей (цвет, графика и т. д.).

### 0.6. Примеры и инфраструктура

- 16 примеров (`01-counter` … `16-studio`) + `annex`, `07-ssh`.
- e2e-модуль для PTY, бенчмарки, phaseprofile, soak-тест, apiaudit.
- Документация: QUICKSTART, ARCHITECTURE, ANIMATION, INTERACTION,
  CUSTOM-CONTROL, COMPATIBILITY, PERFORMANCE, MIGRATION.
- Релиз v0.2.0-rc.2, фиксы после него на `main`.

### 0.7. Главные дыры (почему план такой большой)

1. Виджетов ~18, у зрелых конкурентов (tview, Textual) — 40–60.
2. Layout только Flex — нет Grid, нет абсолютного позиционирования слоями.
3. Тема из 5 ролей — это не дизайн-система.
4. Нет rich text (строка из кусков с разными стилями) как первоклассного
   объекта.
5. Нет keymap-системы для пользователя приложения, нет аккордов.
6. Нет инструментов: инспектора, записи сессий, тест-пакета для приложений.
7. Нет сайта документации, cookbook, гайдов миграции.
8. Нет флагманских приложений, которые «продают» библиотеку.
9. Нет доступности (скринридеры), IME, RTL.
10. Ячейка тяжёлая (80 байт) — на больших экранах это лишняя работа.

## Часть I. Принципы, которые не нарушаем

Эти правила важнее любого пункта плана. Если пункт им противоречит — пункт
переделывается.

1. **Корректность раньше фич.** Терминал никогда не остаётся сломанным.
   Ни одной потерянной клавиши. Ни одного «съехавшего» символа.
2. **Ноль лишнего.** В простое — 0 байт и 0 CPU. В кадре — 0 аллокаций в
   горячем пути.
3. **Три зависимости.** `x/sys`, `x/term`, `uniseg`. Всё остальное — своё.
   Подсветку синтаксиса, markdown, графики — пишем сами, маленькими.
4. **Деградация вместо поломки.** Любая фича имеет лестницу:
   лучший терминал → обычный → `TERM=dumb` → pipe. Смысл сохраняется всегда.
5. **Честные цифры.** Любое «быстрее» — воспроизводимый бенчмарк в репо.
6. **Простой API.** Новичок пишет первое приложение за 15 минут. Сложное —
   возможно, но не обязательно.
7. **Immediate-mode остаётся.** Не добавляем retained-дерево виджетов,
   DOM, виртуальный DOM, реактивность в стиле React. Состояние живёт в модели
   пользователя, виджет — функция отрисовки + маленький `*State`.
8. **Каждый виджет нужен реальному приложению.** Сначала сценарий, потом
   виджет. Не «для коллекции».
9. **Тест на каждую фичу.** Без теста фича не сделана.
10. **Пример на каждую видимую фичу.** В студии или отдельном примере.

## Часть III. Ядро рантайма

Цель: цикл событий, на который можно положиться в приложении, работающем
неделями, с тысячами событий в секунду и сотнями фоновых задач.

### III.1. События и сообщения

- [ ] `[CORE-01]` **Отправка событий снаружи.** `lux.Program` (или функция
  `Send` из контекста), чтобы любая горутина могла безопасно положить
  событие в цикл: вебсокет, файловый watcher, таймер. Сейчас — только через
  `Command`. Тест: 100 горутин × 10 000 событий, ни одно не потеряно, порядок
  внутри горутины сохранён.
- [ ] `[CORE-02]` **Пакетная команда.** `lux.Batch(cmds...)` — запустить
  несколько команд параллельно; `lux.Sequence(cmds...)` — по очереди.
- [ ] `[CORE-03]` **Таймеры.** `lux.After(d, event)` и `lux.Every(d, fn)` с
  отменой. Тики выравниваются по реальному времени, а не накапливают дрейф.
  Ни одного тика, когда приложение приостановлено (Ctrl+Z).
- [ ] `[CORE-04]` **Подписки.** Модель объявляет «я хочу получать события X,
  пока выполняется условие» (таймер, канал, сигнал). Рантайм сам
  подписывает/отписывает между кадрами. Без утечек горутин — тест с
  baseline горутин (как `TestRunReturnsToTheGoroutineBaseline`).
- [ ] `[CORE-05]` **Отмена команд.** Каждая `Command` получает `context`,
  который отменяется при `Quit`; плюс ключ команды: запуск новой команды с
  тем же ключом отменяет старую (поиск по мере ввода, debounce).
- [ ] `[CORE-06]` **Debounce и throttle** как готовые помощники поверх
  ключей команд: `lux.Debounce(key, 200*time.Millisecond, cmd)`.
- [ ] `[CORE-07]` **Приоритеты событий.** Ввод пользователя никогда не стоит
  в очереди за 10 000 событиями от фоновой задачи. Две очереди: ввод и всё
  остальное; ввод обрабатывается первым. Тест: фоновый поток событий
  100k/с, нажатие клавиши отражается на экране ≤ 1 кадра.
- [ ] `[CORE-08]` **Схлопывание.** События одного типа «последнее важнее»
  (движение мыши, ресайз, прогресс задачи) склеиваются, если не успели
  обработаться. Явная пометка для пользовательских событий.
- [ ] `[CORE-09]` **Стрим из команды.** Команда может отдавать много событий
  (прогресс загрузки, строки лога) через канал, а не одно. Корректное
  закрытие, backpressure.

### III.2. Жизненный цикл

- [ ] `[CORE-10]` **Inline-режим.** Работа без alt-screen: приложение рисует
  N строк под курсором (как prompt, селектор, прогресс-бары), по выходу
  результат остаётся в истории терминала. Это половина реальных CLI (gum,
  fzf, npm install). Отдельная опция `WithInline(height)`.
- [ ] `[CORE-11]` **Печать над приложением.** В inline-режиме и в
  полноэкранном — `Println` в историю терминала (лог над интерфейсом), не
  ломая кадр.
- [ ] `[CORE-12]` **Переключение alt-screen ↔ inline на лету** (как less →
  выход с сохранением экрана).
- [ ] `[CORE-13]` **Exec внешней программы.** Приостановить lux, отдать
  терминал `$EDITOR`/`git commit`/`ssh`, по возврату — полная перерисовка.
  Работает на Windows и Unix. Тест через PTY и ConPTY-харнесс.
- [ ] `[CORE-14]` **Хуки жизненного цикла**: `Init` (первая команда),
  `OnSuspend`, `OnResume`, `OnResize`, `OnFocusLost`, `OnQuit` (последний
  шанс сохранить состояние). Без новых интерфейсов, если можно обойтись
  событиями.
- [ ] `[CORE-15]` **Мягкий выход.** Первый Ctrl+C — событие в модель
  («вы уверены?»), второй за 1 с — принудительный выход. Настраивается.
- [ ] `[CORE-16]` **Сигналы**: SIGHUP (терминал закрыли) → `OnQuit` с
  таймаутом, SIGTERM, SIGWINCH, SIGCONT. Windows: CTRL_CLOSE_EVENT,
  CTRL_LOGOFF_EVENT, CTRL_SHUTDOWN_EVENT.
- [ ] `[CORE-17]` **Несколько программ подряд в одном процессе** (wizard →
  основное приложение → итоговый экран) без утечек и мусора на экране.
- [ ] `[CORE-18]` **Вложенный Run** запрещён явно и понятной ошибкой.

### III.3. Ошибки и диагностика

- [ ] `[CORE-19]` **Единая модель ошибок.** Все ошибки рантайма —
  типизированные (`errors.Is/As`): терминал недоступен, не TTY, размер 0,
  ошибка записи, паника модели. Документация «какая ошибка когда».
- [ ] `[CORE-20]` **Отчёт о панике.** При панике: восстановить терминал,
  напечатать понятный заголовок, стек, последние 20 событий (если включено),
  версию lux и возможности терминала. Опционально — сохранить в файл.
- [ ] `[CORE-21]` **Debug-лог.** `LUX_DEBUG=/path/to/file` пишет события,
  тайминги кадров, решения пробинга. Ноль стоимости, если выключено.
- [ ] `[CORE-22]` **Watchdog.** Если `Update` или `View` дольше N мс —
  предупреждение в debug-лог с именем события. Помогает найти «почему
  тормозит».

### III.4. Состояние и данные

- [ ] `[CORE-23]` **Сохранение состояния UI** (открытая вкладка, ширина
  панелей, история ввода) — помощник для сериализации `*State` виджетов в
  JSON. Файл в `os.UserConfigDir()`. Опционально.
- [ ] `[CORE-24]` **Детерминированное время.** Абстракция часов для тестов:
  все таймеры, анимации, debounce работают от подменяемых часов. Тест
  анимации за 0 мс реального времени.
- [ ] `[CORE-25]` **Детерминированный рандом** для демо и тестов (seed).

**Готово, когда:** 3 флагманских приложения (часть XVII) построены без единого
«костыля вокруг рантайма»; soak 24 ч с внешними событиями — память плоская.

## Часть IV. Рендер-движок

Цель: самый эффективный вывод в терминал из существующих библиотек, при
полной корректности на любом терминале.

### IV.1. Ячейка и буфер

- [ ] `[RND-01]` **Лёгкая ячейка.** `Cell` 80 → ≤ 16 байт:
  - стиль — индекс в таблице стилей кадра (интернирование);
  - графема — либо руна прямо в ячейке (99% случаев), либо индекс в пуле
    строк для кластеров;
  - ссылка — индекс в таблице ссылок.
  API `Cell` меняется → `docs/MIGRATION.md`, отдельный минорный релиз.
  Бенчмарк до/после: заливка, текст, диф 200×60 и 400×120.
- [ ] `[RND-02]` **Грязные строки.** Буфер помнит, какие строки менялись
  с прошлого кадра; диф проверяет только их. Кадр, где поменялась одна
  цифра, — O(ширина), а не O(экран).
- [ ] `[RND-03]` **Слои (z-order).** Отрисовка в несколько слоёв (основной,
  поповеры, тултипы, тосты, модалки) с автоматическим порядком. Сейчас
  модалка рисуется «поверх» руками.
- [ ] `[RND-04]` **Прозрачность и затемнение.** Слой может затемнять
  нижний (backdrop модалки: dim всех ячеек под ним), тень под поповером.
- [ ] `[RND-05]` **Offscreen-буферы.** Нарисовать виджет в отдельный буфер и
  переиспользовать, пока данные не поменялись (кэш тяжёлых графиков,
  markdown).
- [ ] `[RND-06]` **Скролл-регионы.** Использовать DECSTBM / `ScrollRows` для
  прокрутки логов: при добавлении строки внизу — 1 строка вывода, а не
  перерисовка всего лога. (Частично есть — довести до всех скроллящихся
  виджетов.)

### IV.2. Вывод

- [ ] `[RND-07]` **Synchronized output (mode 2026)** везде, где поддержан:
  кадр появляется целиком, без мерцания. Пробинг + деградация.
- [ ] `[RND-08]` **Бюджет байтов на медленной линии.** Если кадр больше
  N КБ и линия медленная (SSH 56 кбит/с) — разбить обновление, отдавая
  приоритет области фокуса. Тест на эмулированной медленной линии.
- [ ] `[RND-09]` **Повторное использование стиля.** Энкодер не повторяет SGR,
  если стиль соседней ячейки тот же; переходы между стилями — кратчайшие
  (частично есть — замерить и добить).
- [ ] `[RND-10]` **ECH/REP/ICH/DCH** — использовать «стереть N символов»,
  «повторить символ N раз», «вставить/удалить символы», где это короче.
  Только при положительном пробинге.
- [ ] `[RND-11]` **Восстановление после рассинхрона.** Если терминал
  ответил неожиданным размером/позицией курсора — полная перерисовка.
  Горячая клавиша «перерисовать всё» (Ctrl+L) — встроенная по умолчанию.

### IV.3. Рисование

- [ ] `[RND-12]` **Расширенные рамки.** Наборы: тонкая, жирная, двойная,
  скруглённая, пунктирная, ASCII, «блочная» (▛▀▜), невидимая. Заголовок на
  рамке слева/по центру/справа, подпись снизу, иконка в углу.
- [ ] `[RND-13]` **Соединение рамок.** Соседние панели делят линию с
  правильными тройниками (├ ┬ ┼), как в настоящих TUI.
- [ ] `[RND-14]` **Линии и фигуры.** Горизонталь, вертикаль, прямоугольник,
  линия под углом (Брезенхем) в ячейках и в braille.
- [ ] `[RND-15]` **Braille-канва.** Рисование точками 2×4 на ячейку:
  `Set(x,y)`, линии, окружности, заливка. База для графиков.
- [ ] `[RND-16]` **Полублочная канва.** Пиксели 1×2 на ячейку (▀ ▄) в
  truecolor — для картинок и превью.
- [ ] `[RND-17]` **Квадранты и сексанты** (▖▗▘▙, символы Unicode 13
  «legacy computing») для плавных графиков, с проверкой поддержки шрифтом
  (опция, а не автоматом).
- [ ] `[RND-18]` **Градиенты.** Горизонтальный/вертикальный/диагональный
  градиент фона и текста; смешивание в OKLCH, а не в RGB (не «грязные»
  середины). Деградация до 256/16 с дизерингом или ступенями.
- [ ] `[RND-19]` **Тени.** Мягкая тень под поповером/модалкой (полутоновые
  блоки или затемнение фона).

### IV.4. Графика

- [ ] `[RND-20]` **Kitty graphics protocol**: показать PNG/RGBA в
  прямоугольнике ячеек, переиспользовать ID картинки, удаление при
  перерисовке, корректная работа при скролле.
- [ ] `[RND-21]` **Sixel** для терминалов без kitty (foot, WezTerm, mlterm,
  Windows Terminal 1.22+). Своя квантизация палитры.
- [ ] `[RND-22]` **iTerm2 inline images (OSC 1337).**
- [ ] `[RND-23]` **Лестница картинок**: kitty → sixel → iTerm → полублоки →
  ASCII-art → подпись «[image: name.png]». Выбор по пробингу.
- [ ] `[RND-24]` **Декодеры**: PNG, JPEG, GIF через stdlib `image/*`.
  Масштабирование (билинейное) своё.
- [ ] `[RND-25]` **scene3d → картинка.** Рендер 3D-сцены в пиксели и вывод
  через графический протокол при наличии, иначе — текущие ячейки.

**Готово, когда:** кадр 200×60 с одной изменённой ячейкой — меньше 50 байт
вывода и меньше 10 мкс; полноэкранная перерисовка 400×120 — без аллокаций;
картинки работают в kitty, WezTerm, foot, Windows Terminal.

## Часть V. Текст и Unicode

Цель: любой текст на любом языке отображается правильно; стилизованный
текст — первоклассный объект.

### V.1. Rich text

- [ ] `[TXT-01]` **Span-текст.** Тип «строка из кусков», каждый со своим
  стилем и ссылкой: `render.Spans{{Text: "Error: ", Style: danger}, ...}`.
  Все виджеты, где есть текст (List, Table, Tree, Tabs, Button…), принимают
  либо `string`, либо spans.
- [ ] `[TXT-02]` **Перенос span-текста** по словам с сохранением стилей
  между строками.
- [ ] `[TXT-03]` **Выравнивание**: слева, по центру, справа, по ширине
  (justify) — для абзацев.
- [ ] `[TXT-04]` **Обрезка**: с многоточием в конце, в середине
  (`/very/…/path.go`), в начале. Корректно для графем и широких символов.
- [ ] `[TXT-05]` **ANSI-импорт.** Разобрать строку с ANSI-цветами (вывод
  `git diff --color`, `ls --color`, логов) в spans. Без этого невозможно
  показать вывод чужих команд. Чистит опасные последовательности (OSC,
  CSI-перемещения) — это граница доверия.
- [ ] `[TXT-06]` **ANSI-экспорт.** Spans → строка с ANSI (для печати
  результатов в inline-режиме и в лог).
- [ ] `[TXT-07]` **Подсветка совпадений.** Помощник «подсветить буквы,
  совпавшие с fuzzy-запросом» — для палитры, фильтров, поиска.
- [ ] `[TXT-08]` **Мини-разметка (опционально).** `"[bold]Hi[/] [link=url]x[/]"`
  → spans. Только если 3+ примера реально выиграют. Не CSS.

### V.2. Unicode-правда

- [ ] `[TXT-09]` **Таблица ширин актуальной версии Unicode** (16/17),
  генерируется скриптом из официальных данных, проверяется тестом.
- [ ] `[TXT-10]` **Conformance-тесты UAX #29** (графемы) — 100% из
  официального `GraphemeBreakTest.txt`.
- [ ] `[TXT-11]` **Перенос по UAX #14** (правила разрыва строк): не рвать
  перед знаками препинания, правильно для CJK, разрешённые разрывы после
  дефиса, slash, неразрывные пробелы.
- [ ] `[TXT-12]` **Табуляция**: настраиваемая ширина, раскрытие до
  следующей позиции табуляции, корректно внутри spans.
- [ ] `[TXT-13]` **Управляющие символы** в пользовательском тексте видимы и
  безопасны: `\x1b` → `␛`, `\r` → `␍` и т. д. Никогда не попадают в вывод
  сырыми.
- [ ] `[TXT-14]` **Эмодзи**: ZWJ-последовательности, флаги, модификаторы
  тона кожи, VS15/VS16 — ширина совпадает с терминалом (через пробинг и
  WidthPolicy).
- [ ] `[TXT-15]` **Нормализация** (NFC) при сравнении в поиске и фильтрах:
  «é» как одна руна и как e+◌́ находятся одинаково. Своя маленькая таблица
  или осознанный отказ с документацией.
- [ ] `[TXT-16]` **Регистронезависимый поиск** с Unicode case folding
  (stdlib `unicode.SimpleFold`).

### V.3. Двунаправленный текст (RTL)

- [ ] `[TXT-17]` **Исследование**: как текущие терминалы показывают
  арабский/иврит (большинство — без bidi). Записать в COMPATIBILITY.md.
- [ ] `[TXT-18]` **Базовый bidi** для строк: визуальное переупорядочивание
  по упрощённому UAX #9 для отображения строк, где терминал этого не делает.
  Каретка в RTL-поле ввода движется визуально правильно.
- [ ] `[TXT-19]` **Зеркальный layout** (опционально): `layout.Flex` с
  направлением RTL.

### V.4. Шрифты и иконки

- [ ] `[TXT-20]` **Набор иконок** с лестницей: Nerd Font → Unicode-символ →
  ASCII. `ui.Icon("folder")` возвращает лучшее доступное. Пользователь
  выбирает режим (Nerd Fonts не определить пробингом).
- [ ] `[TXT-21]` **Box-drawing fallback** — если шрифт/терминал не умеет
  (`TERM=linux`, старые консоли), рамки автоматически в ASCII.

**Готово, когда:** демо «Unicode-зоопарк» (CJK, эмодзи, арабский, хинди,
тайский, комбинирующие знаки) выглядит корректно в 6 основных терминалах;
вывод `git log --color --graph` показывается в виджете 1:1.

## Часть VI. Ввод: клавиатура, мышь, вставка, IME

Цель: lux-приложение ощущается как нативный редактор. Ни одной
перепутанной клавиши ни в одном терминале и раскладке.

### VI.1. Клавиатура

- [ ] `[INP-01]` **Golden-таблица клавиш.** Для каждого протокола (legacy,
  kitty, win32, xterm modifyOtherKeys) — таблица «байты → событие» из
  реальных записей терминалов. Тест прогоняет всю таблицу.
- [ ] `[INP-02]` **xterm modifyOtherKeys (mode 2)** и CSI-u без kitty —
  для xterm, старых iTerm, mintty.
- [ ] `[INP-03]` **Не-латинские раскладки.** Русская/греческая раскладка:
  Ctrl+С (кириллическая) срабатывает как Ctrl+C. Kitty «base layout key»
  и win32 virtual key используются для шорткатов; текст — по реальной руне.
- [ ] `[INP-04]` **AltGr** на Windows и Linux: AltGr+Q = «@» в немецкой
  раскладке не превращается в Ctrl+Alt+Q.
- [ ] `[INP-05]` **Мёртвые клавиши** (´ + e = é) — приходят одной руной.
- [ ] `[INP-06]` **Numpad, F13–F24, media-клавиши** (громкость, play) — где
  терминал их передаёт.
- [ ] `[INP-07]` **Различение Esc и Alt+X** в legacy-режиме: настраиваемый
  таймаут (по умолчанию 25 мс, на SSH — больше); в kitty-режиме таймаута нет.
- [ ] `[INP-08]` **Повтор клавиши** (repeat) отдельно от первого нажатия,
  если терминал сообщает.
- [ ] `[INP-09]` **Модификаторы-одиночки** (нажали и отпустили Shift) — в
  kitty-режиме с release.
- [ ] `[INP-10]` **Человекочитаемые клавиши.** `event.ParseKey("ctrl+shift+p")`
  и `key.String()` → `"Ctrl+Shift+P"`, плюс macOS-вид `⌃⇧P`.

### VI.2. Keymap-система

- [ ] `[INP-11]` **Привязки как данные.** `keymap.Map{"save": {"ctrl+s"},
  "quit": {"q", "ctrl+c"}}` → проверка «это действие save?» одной функцией.
  Действие с описанием и группой (для справки).
- [ ] `[INP-12]` **Скоупы.** Глобальные, экранные, виджетные привязки;
  приоритет «самый внутренний фокус выигрывает» (база есть в `Shortcut`,
  довести до keymap).
- [ ] `[INP-13]` **Аккорды.** `"g g"`, `"ctrl+k ctrl+s"`, `"space f f"`
  (как в Vim/VS Code). Индикатор «ожидаю следующую клавишу» в статус-баре,
  таймаут, Esc отменяет.
- [ ] `[INP-14]` **Count-префиксы** Vim-стиля (`5j`) — опционально,
  включаемо.
- [ ] `[INP-15]` **Переназначение пользователем.** Загрузка keymap из
  JSON/TOML-подобного файла (свой простой парсер или JSON из stdlib).
- [ ] `[INP-16]` **Проверка конфликтов.** Две команды на одну клавишу в
  одном скоупе — ошибка при старте (в debug) с понятным сообщением.
- [ ] `[INP-17]` **Автосправка.** `ui.HelpView(keymap)` — окно `?` со всеми
  привязками по группам; короткая строка подсказок внизу экрана
  (`↑↓ move · enter open · q quit`), которая сжимается по ширине.
- [ ] `[INP-18]` **Пресеты**: «default», «vim», «emacs» для навигации в
  списках/полях ввода.

### VI.3. Мышь

- [ ] `[INP-19]` **Двойной и тройной клик** с настраиваемым интервалом;
  в TextInput/TextArea — выделение слова/строки.
- [ ] `[INP-20]` **Драг с порогом** (не начинать драг от дрожания на

- [ ] `[INP-21]` **Drag & drop** между виджетами: источник, цель,

- [ ] `[INP-22]` **Горизонтальный скролл** (Shift+колесо и тачпад).
- [ ] `[INP-23]` **Плавная прокрутка тачпадом**: пиксельная мышь даёт
  дробный скролл; накопление и инерция.
- [ ] `[INP-24]` **Курсор мыши** (OSC 22): pointer над кнопками, text над

- [ ] `[INP-25]` **Hover-задержка** для тултипов (500 мс), уход мыши за

**Готово, когда:** golden-таблица на 500+ записей, ноль расхождений; в

## Часть VII. Layout

Цель: собрать любой экран (IDE, дашборд, форма, мобильно-узкий терминал) в
несколько строк, без ручной арифметики координат. Без CSS и без Yoga —
свои простые функции поверх `render.Rect`.

### VII.1. Примитивы

- [ ] `[LAY-01]` **Доработка Flex**: `gap`, `padding`, `margin`, выравнивание
  по главной и поперечной оси (start/center/end/stretch/space-between),
  `min`/`max` у каждого элемента, перенос на новую строку (wrap).
- [ ] `[LAY-02]` **Grid.** Колонки и строки: фиксированные, проценты, `fr`,
  `auto` (по содержимому), `minmax`. Элемент может занимать несколько ячеек
  (span). Именованные области (`"header header" "nav main"`) — как массив
  строк, не CSS-парсер.
- [ ] `[LAY-03]` **Stack/Overlay.** Несколько элементов в одном
  прямоугольнике с якорями: центр, углы, «прилипнуть к низу» — для
  поповеров, тостов, плавающих кнопок.
- [ ] `[LAY-04]` **Dock.** Прилепить к краю (top/bottom/left/right),
  остаток — центру. Классический каркас «меню сверху, статус снизу,
  сайдбар слева».
- [ ] `[LAY-05]` **Split.** Разделение на N частей с весами; веса меняет
  драг мышью или клавиши (часть компонента SplitPane, X.7).
- [ ] `[LAY-06]` **Центрирование и aspect ratio.** «Окно 60×20 по центру,
  но не больше 90% экрана».
- [ ] `[LAY-07]` **Intrinsic size.** Виджеты сообщают желаемый размер
  (`Measure(maxWidth) (w, h)`), layout учитывает. Кнопка по ширине текста,
  таблица по колонкам.

### VII.2. Адаптивность

- [ ] `[LAY-08]` **Брейкпоинты** (доработка `Classify`): `compact`,
  `medium`, `wide`, `ultra` по ширине и высоте; пример «сайдбар исчезает в
  compact, вкладки становятся меню».
- [ ] `[LAY-09]` **Сворачивание декора.** Порядок, в котором экран
  «худеет»: убрать тени → убрать рамки → сократить подписи → скрыть
  второстепенные колонки → стек вместо колонок → скролл. Помощник для
  таблиц: приоритет колонок.
- [ ] `[LAY-10]` **Минимальный размер экрана.** Если окно меньше минимума —
  понятная заглушка «Сделайте окно больше (нужно 40×10)», а не каша.

### VII.3. Скролл и виртуализация

- [ ] `[LAY-11]` **Скролл-контейнер для произвольного содержимого**
  (доработка ScrollViewport): вертикальный, горизонтальный, оба;
  скроллбары, которые можно тащить мышью; клик по дорожке листает страницу.
- [ ] `[LAY-12]` **Sticky.** Прилипающие заголовки секций и строк таблицы
  при прокрутке.
- [ ] `[LAY-13]` **Виртуализация.** Контейнер знает только число элементов и
  функцию «нарисуй элемент i»; рисует видимые. Переменная высота элементов
  с кэшем измерений.
- [ ] `[LAY-14]` **Scroll-into-view** для любого региона (фокус ушёл за
  экран → прокрутить). База есть — довести до вложенных контейнеров любой
  глубины.

## Часть VIII. Стили, темы, дизайн-система

Цель: красиво по умолчанию, в любой теме, без работы со стороны
разработчика. Сейчас тема из 5 ролей — нужно полноценное «дизайн-ядро».

### VIII.1. Токены

- [ ] `[STY-01]` **Цветовые токены по смыслу.** Минимальный набор:
  `bg`, `bg.subtle`, `surface`, `surface.raised`, `overlay`, `border`,
  `border.strong`, `text`, `text.muted`, `text.disabled`, `text.inverse`,
  `accent`, `accent.subtle`, `accent.fg`, `focus.ring`, `selection`,
  `success`, `warning`, `danger`, `info` (+ `.subtle`, `.fg` к каждому),
  `link`, `link.visited`. Сейчас Theme из 5 полей — расширить с миграцией.
- [ ] `[STY-02]` **Токены отступов и размеров**: `space.0…6`, ширина
  рамки, стиль рамки по умолчанию, скругление (скруглённые/прямые углы),
  плотность (compact/comfortable).
- [ ] `[STY-03]` **Состояния компонентов.** Каждый интерактивный виджет:
  `normal`, `hover`, `pressed`, `focused`, `selected`, `disabled`,
  `invalid`, `loading`. Стиль каждого состояния выводится из токенов, не
  задаётся руками в каждом виджете.
- [ ] `[STY-04]` **Компонентные стили.** `ButtonStyle`, `ListStyle` и т. д.
  строятся из темы одной функцией (`theme.Button()`); пользователь
  переопределяет только то, что хочет.
- [ ] `[STY-05]` **Варианты** у компонентов: `primary`, `secondary`,
  `ghost`, `danger`, `link` для кнопок; `bordered`, `flat` для панелей.

### VIII.2. Цвет

- [ ] `[STY-06]` **Определение фона терминала** (OSC 10/11 запрос цвета
  текста и фона) → автоматический выбор light/dark темы. Таймаут, кэш на
  сессию, переопределение переменной окружения.
- [ ] `[STY-07]` **Палитра терминала** (OSC 4) — опционально использовать
  реальные 16 цветов пользователя, чтобы тема совпадала с его схемой.
- [ ] `[STY-08]` **OKLCH-математика**: осветлить/затемнить/смешать/
  полупрозрачность поверх фона — для hover-состояний и `.subtle`-токенов,
  генерируемых из одного базового цвета.
- [ ] `[STY-09]` **Проверка контраста** (WCAG/APCA) — тест, что во всех
  встроенных темах текст на фоне читаем. Функция для пользовательских тем.
- [ ] `[STY-10]` **Понижение цвета**: truecolor → 256 (ближайший в
  перцептивном пространстве) → 16 → моно; `NO_COLOR` уже работает — не
  сломать; `FORCE_COLOR`, `COLORTERM`.
- [ ] `[STY-11]` **Моно-режим как полноценный.** Без цвета интерфейс
  остаётся понятным: фокус — reverse/underline, ошибки — `!` префикс.

### VIII.3. Темы

- [ ] `[STY-12]` **Встроенные темы**: `default` (только атрибуты, как
  сейчас), `dark`, `light`, `high-contrast-dark`, `high-contrast-light`.
- [ ] `[STY-13]` **Популярные схемы**: Catppuccin (4 варианта), Tokyo Night,
  Nord, Dracula, Gruvbox (dark/light), Solarized (dark/light), One Dark,

- [ ] `[STY-14]` **Своя тема из 1–3 цветов.** `theme.FromAccent(color)` —

- [ ] `[STY-15]` **Загрузка темы из файла** (JSON) и горячая перезагрузка
  при изменении файла (для дизайнеров — правишь файл, видишь сразу).
- [ ] `[STY-16]` **Переключение темы на лету** с плавным переходом цвета
  (motion), без мерцания.

### VIII.4. Визуальный язык

- [ ] `[STY-17]` **Гайд «как сделать красиво»** (docs/DESIGN.md): сетка
  отступов, иерархия текста, когда рамка, когда фон, цвет только для

- [ ] `[STY-18]` **Галерея** в студии: все компоненты × все состояния × все

## Часть IX. Анимация и motion

Цель: плавные, уместные, отключаемые анимации, которые не жрут CPU.
База (Tween, Spring, абсолютное время, reduced motion, адаптивный FPS) уже
сильная — расширяем.

- [ ] `[MOT-01]` **Библиотека изингов**: полный набор (Sine, Quad, Cubic,
  Quart, Expo, Circ, Back, Elastic, Bounce × In/Out/InOut), `cubic-bezier`
  с 4 параметрами, `steps(n)`.
- [ ] `[MOT-02]` **Пресеты пружин**: `gentle`, `snappy`, `bouncy`, `stiff`
  — с понятными названиями, а не stiffness/damping.
- [ ] `[MOT-03]` **Таймлайны**: последовательность, параллель, задержка,
  повтор, реверс. `motion.Sequence(a, b).Then(c)`.
- [ ] `[MOT-04]` **Stagger**: элементы списка появляются по очереди с
  шагом N мс.
- [ ] `[MOT-05]` **Прерываемость**: новая цель посреди анимации —
  продолжить из текущей позиции и скорости, без скачка (пружины уже умеют,
  довести твины).
- [ ] `[MOT-06]` **Анимация цвета** в OKLCH (hover, переключение темы).
- [ ] `[MOT-07]` **Переходы экранов**: slide (влево/вправо/вверх), fade
  (через затемнение цветом фона), «push/pop» для навигации.
- [ ] `[MOT-08]` **Появление/исчезновение** модалок, поповеров, тостов
  (масштаб через рамку, выезд, fade).
- [ ] `[MOT-09]` **Анимация списков**: вставка/удаление строки
  раздвигает/схлопывает соседей; перестановка элементов плавно.
- [ ] `[MOT-10]` **Плавный скролл** колесом и PageDown (отключается в
  reduced motion).
- [ ] `[MOT-11]` **Анимация layout**: ширина панели меняется плавно при
  сворачивании сайдбара.
- [ ] `[MOT-12]` **Числа**: счётчики «докручиваются» до нового значения
  (метрики дашборда).
- [ ] `[MOT-13]` **Бюджет**: анимация не поднимает FPS выше нужного
  (спиннеру 10 кадров/с хватит), все анимации останавливаются при потере
  фокуса окна (опционально) и при suspend.
- [ ] `[MOT-14]` **Reduced motion** везде: переходы заменяются мгновенными,
  спиннеры — статичным индикатором, мерцаний нет. Автоопределение из
  переменной окружения + опция.
- [ ] `[MOT-15]` **Отладка анимаций**: замедление времени ×0.1 горячей
  клавишей в DevTools.

**Готово, когда:** у каждого перехода в студии есть анимация и она
отключается одной опцией; CPU в простое с открытыми, но неактивными
анимациями — 0%.

## Часть X. Компоненты — полный каталог

Цель: типичное приложение (git-клиент, мониторинг, админка, редактор,
чат, файловый менеджер) собирается **без единого самописного виджета**.

### X.0. Обязательно для КАЖДОГО компонента

Компонент не считается сделанным, пока у него нет всего списка
(чек-лист — приложение B):

1. Клавиатура: полная навигация без мыши, стандартные клавиши.
2. Мышь: клик, hover, колесо, драг (где уместно).
3. Фокус: видимое фокус-кольцо, Tab/Shift+Tab, программный фокус.
4. Все состояния из `[STY-03]`: hover, pressed, focused, disabled, invalid…
5. Тема: стиль только из токенов, работает во всех встроенных темах и в
   моно-режиме.
6. Размеры: не паникует на 0×0, 1×1; осмысленно при узкой ширине.
7. Unicode: CJK, эмодзи, комбинирующие знаки в содержимом.
8. Доступность: роль, имя и состояние для announcer (`[A11Y-02]`).
9. Нулевые аллокации при перерисовке без изменений (бюджет в
   `alloc_guard_test.go`).
10. Godoc с `Example*`, страница в документации, пример в студии/галерее.
11. Golden-снимок (снимок кадра) + тесты состояния + мутационная проверка.

## Часть XII. Производительность

Цель: самая быстрая TUI-библиотека, доказанно. Цифры ниже — цели, а не
текущие результаты. Каждая проверяется бенчмарком в `benchmarks/`.

### XII.1. Бюджеты

| Сценарий | Цель |
|---|---|
| Простой (нет событий) | 0 байт, 0 кадров, 0% CPU, 0 горутин-тикеров |
| Старт до первого кадра | ≤ 50 мс (с пробингом), ≤ 10 мс без |
| Ввод → кадр на экране | ≤ 1 кадр (≤ 16 мс при 60 FPS) |
| Изменение 1 ячейки, экран 200×60 | ≤ 50 байт, ≤ 10 мкс |
| Полная перерисовка 200×60 | ≤ 200 мкс, 0 аллокаций |
| Полная перерисовка 400×120 | ≤ 800 мкс, 0 аллокаций |
| Лог: поток 100 000 строк/с | UI отзывчив, память ограничена |
| Таблица 1 000 000 строк | скролл 60 FPS, память ≤ 2× данных |
| TextArea 10 МБ файл | ввод символа ≤ 1 мс |
| 24 ч сессия с анимацией | память плоская (±1 МБ) |
| SSH 56 кбит/с | интерфейс пригоден, приоритет фокуса |
| Память на пустое приложение | ≤ 2 МБ сверх рантайма Go |

## Часть XIII. Надёжность и тестирование

Цель: библиотеке можно доверить продакшен-инструмент, который работает

### XIII.1. Гарантии

- [ ] `[REL-01]` **Терминал всегда восстанавливается**: нормальный выход,
  ошибка, паника в любом месте (Update, View, Command, хуки, анимации),
  SIGTERM, SIGHUP, kill -9 родителя SSH, закрытие окна, Ctrl+Break на
  Windows. Таблица «что происходит» + e2e-тест на каждую строку, где это
  технически возможно (kill -9 самого процесса восстановить нельзя —
  задокументировать и дать `lux reset`-утилиту).
- [ ] `[REL-02]` **Утилита восстановления.** `go run
  github.com/GofMan5/lux/cmd/luxreset` — сбросить сломанный терминал
  (выключить мышь, kitty-клавиатуру, alt-screen, показать курсор).
- [ ] `[REL-03]` **Нет потерянных событий**: под нагрузкой ни одна
  клавиша не теряется и не переставляется (тест с заданной
  последовательностью из 100 000 клавиш).
- [ ] `[REL-04]` **Нет утечек**: горутины, память, файловые дескрипторы

  все опции и все бэкенды).

### XIII.2. Тесты

- [ ] `[REL-05]` **Fuzz парсера ввода** — часы CPU без паник, с

- [ ] `[REL-06]` **Fuzz рендера**: случайный текст/стили/размеры →

- [ ] `[REL-07]` **Fuzz виджетов**: случайные события и размеры для

- [ ] `[REL-09]` **Golden-снимки** всех примеров и всех компонентов ×

- [ ] `[REL-10]` **VT-конформность**: вывод lux проверяется эмулятором,

- [ ] `[REL-11]` **Мутационное тестирование** ключевых пакетов

- [ ] `[REL-14]` **Race detector** на всех тестах (уже — сохранить).

## Часть XIV. Доступность и языки

Цель: первая в Go-мире TUI-библиотека, которой можно пользоваться со
скринридером. У Bubble Tea и tview это открыто годами.

### XIV.1. Скринридеры

- [ ] `[A11Y-01]` **Исследование**: как NVDA, JAWS, Narrator (Windows),
  VoiceOver (macOS), Orca (Linux) читают терминал; какие паттерны
  работают (каретка в месте фокуса, линейный вывод).
- [ ] `[A11Y-02]` **Семантика**: каждый компонент сообщает роль (button,
  checkbox, list, listitem…), имя, состояние (checked, expanded, 3 из 10).
- [ ] `[A11Y-03]` **Announcer-порт**: при смене фокуса и важных событиях
  (ошибка формы, тост) — текст для озвучивания. Реализации: через
  каретку+строку статуса (работает со всеми скринридерами в терминале),
  через OSC (если появится стандарт), через платформенный API (отдельный
  модуль, опционально).
- [ ] `[A11Y-04]` **Каретка на фокусе**: терминальная каретка всегда
  стоит на фокусированном элементе — скринридеры читают строку под ней.
- [ ] `[A11Y-05]` **Линейный режим** (`WithAccessible`): без анимаций,
  без рамок-украшений, без мерцающих спиннеров, интерфейс как
  последовательность понятных строк.
- [ ] `[A11Y-06]` **Проверка с реальным скринридером** (NVDA на Windows —
  бесплатный): записать результаты по каждому компоненту.

### XIV.2. Зрение и моторика

- [ ] `[A11Y-07]` **High-contrast темы** (`[STY-12]`) и тест контраста.
- [ ] `[A11Y-08]` **Дальтонизм**: ни одно состояние не передаётся только
  цветом (всегда + символ/текст); проверка тем симуляцией протанопии/
  дейтеранопии.
- [ ] `[A11Y-09]` **Только клавиатура**: каждое действие доступно без
  мыши (проверка по чек-листу для каждого компонента).
- [ ] `[A11Y-10]` **Только мышь**: основные сценарии выполнимы мышью
  (для пользователей, которым тяжело с клавиатурой).
- [ ] `[A11Y-11]` **Reduced motion** (`[MOT-14]`) — без мерцаний чаще
  3 раз в секунду (защита от эпилепсии).
- [ ] `[A11Y-12]` **Крупный режим**: увеличенные отступы и цели кликов
  (плотность `comfortable`).

### XIV.3. Языки и локализация

- [ ] `[A11Y-13]` **Встроенные строки** компонентов (OK, Cancel, «Нет
  данных», «Загрузка…», дни недели, месяцы) — через таблицу локализации;
  en по умолчанию, ru, de, fr, es, pt, ja, zh, ko из коробки.
- [ ] `[A11Y-14]` **Форматы**: числа (1,234.5 / 1 234,5), даты, размеры
  файлов, относительное время («5 минут назад») — по локали.
- [ ] `[A11Y-15]` **CJK**: ширины, перенос без пробелов, IME
  (`[INP-33]`, `[INP-34]`).
- [ ] `[A11Y-16]` **RTL** (`[TXT-17]`–`[TXT-19]`).
- [ ] `[A11Y-17]` **Определение локали** из `LANG`/`LC_ALL`/Windows API.

**Готово, когда:** студия полностью управляется с NVDA (записано видео/
протокол); все компоненты имеют роли; 9 языков встроенных строк.

## Часть XV. Опыт разработчика (DX)

Цель: lux выбирают, потому что с ней приятно работать. Первое приложение —
15 минут, серьёзное — без чтения исходников библиотеки.

### XV.1. API

- [ ] `[DX-01]` **Ревью всего публичного API** по правилам: понятные
  имена, полезное нулевое значение, никаких bool-параметров подряд
  (`f(true, false, true)`), опции вместо длинных сигнатур, ошибки, а не
  паники (кроме ошибок программиста, как дубли ID), согласованность
  (`XxxState`, `XxxStyle`, `ctx.Xxx(id, canvas, bounds, state, …)`).
- [ ] `[DX-02]` **Короткий путь** для частых случаев: виджет без явного
  `ID` (авто-ID по месту вызова — только если безопасно), стиль из темы по
  умолчанию, `bounds` из layout-помощника.
- [ ] `[DX-03]` **Понятные паники**: дубль ID, `Begin` без `End`, виджет
  вне кадра — сообщение говорит, что не так и как исправить, со ссылкой на
  документацию.
- [ ] `[DX-04]` **go vet-анализатор** `luxvet`: ловит типичные ошибки
  (State по значению вместо указателя, ID в цикле без индекса, блокирующий
  вызов в `Update`). Отдельный модуль на `golang.org/x/tools` (зависимость
  только у анализатора, не у библиотеки).
- [ ] `[DX-05]` **apiaudit** (уже есть) — снимок публичного API в репо,
  тест падает при случайном изменении API.

### XV.2. Документация

- [ ] `[DX-06]` **Сайт документации** (статический, генерируется из

- [ ] `[DX-07]` **Tutorial «Первое приложение»** — счётчик → список дел

- [ ] `[DX-08]` **Tutorials** (каждый — законченное приложение):

- [ ] `[DX-09]` **Гайды по темам**: архитектура приложения (модель,

  SSH-приложения, доступность, inline-режим, распространение приложения

- [ ] `[DX-10]` **Cookbook — 50 рецептов** (каждый ≤ 100 строк,

  палитра команд, тосты, прогресс загрузки файла, отмена долгой задачи,
  тёмная/светлая тема по системе, своя тема из цвета, keymap из файла,

## Часть XVI. Слой приложения (app shell)

Цель: «каркас» серьёзного приложения из коробки, чтобы каждый не писал
заново роутинг экранов, keymap, настройки и справку. Это **отдельный
необязательный пакет** (`lux/app`), ядро остаётся минимальным.

- [ ] `[APP-01]` **Экраны и роутер**: стек экранов, у каждого свои
  `Update/View`, keymap, заголовок; push/pop/replace, «назад»,
  анимированный переход, сохранение состояния ушедшего экрана.
- [ ] `[APP-02]` **Глобальный keymap + палитра команд**, автоматически
  собранные из команд всех экранов.
- [ ] `[APP-03]` **Стандартный каркас**: заголовок, сайдбар, контент,
  статус-бар, подсказки клавиш — настраиваемые слоты.
- [ ] `[APP-04]` **Настройки**: экран настроек, генерируемый из
  структуры Go (поля → контролы), сохранение в файл в `UserConfigDir`.
- [ ] `[APP-05]` **Справка** `?` и «О программе» из метаданных.
- [ ] `[APP-06]` **Уведомления**: тосты + центр уведомлений как сервис.
- [ ] `[APP-07]` **Фоновые задачи**: менеджер задач с прогрессом,
  отменой, списком в отдельной панели (как Jobs в студии).
- [ ] `[APP-08]` **Логи приложения**: встроенная панель логов
  (`log/slog`-хендлер → LogView), открывается горячей клавишей.
- [ ] `[APP-09]` **Подтверждение выхода** при несохранённых данных.
- [ ] `[APP-10]` **Конфиг и флаги**: путь конфига, `--theme`, `--no-mouse`,
  `--reduced-motion`, `--accessible` — стандартные флаги одной строкой
  (через stdlib `flag`).
- [ ] `[APP-11]` **Одиночный экземпляр / восстановление сессии**
  (опционально): открыть последние вкладки при перезапуске.

**Готово, когда:** флагманские приложения используют `lux/app` и каждое
меньше на 30% кода, чем без него.

## Часть XVII. Флагманские приложения

Библиотеку продают приложения. Они же — главный источник правды о том,
чего не хватает. Каждое — отдельный репозиторий, настоящий полезный
инструмент, публичный релиз, бинарники под все ОС.

### XVII.1. Три основных

- [ ] `[APPS-01]` **luxgit — Git-клиент** (уровень lazygit/gitui):
  - статус с индексом/рабочим деревом, stage/unstage по файлам и ханкам;
  - коммит с редактором сообщения, amend;
  - лог с графом веток, поиск, просмотр коммита и diff;
  - ветки: создать, переключить, удалить, merge, rebase (с конфликтами);
  - stash, теги, remote, push/pull/fetch с прогрессом;
  - blame, история файла;
  - работа через `git` CLI (exec), без библиотек.
- [ ] `[APPS-02]` **luxtop — системный монитор** (уровень btop):
  - CPU по ядрам с графиками, память/swap, сеть, диски, температура,
    батарея;
  - процессы: дерево, сортировка, фильтр, kill, приоритет;
  - Linux, macOS, Windows, FreeBSD (свои сборщики метрик через
    `/proc`, sysctl, Windows API из `x/sys`);
  - темы, раскладки панелей, конфиг.
- [ ] `[APPS-03]` **luxlog — просмотр логов и JSON** (уровень lnav):
  - файлы любого размера (mmap/стриминг), tail -f, несколько файлов;
  - автоопределение формата (JSON-строки, logfmt, syslog, nginx);
  - фильтры, поиск, подсветка, переход по времени, гистограмма событий;
  - просмотр JSON-документа деревом.

### XVII.2. Дополнительные (выбрать по интересу)

- [ ] `[APPS-04]` **luxfm** — файловый менеджер (как yazi/ranger): две
  панели, превью (текст, картинки, архивы), операции с прогрессом.
- [ ] `[APPS-05]` **luxhttp** — HTTP-клиент: коллекции запросов, история,
  просмотр JSON-ответа, переменные окружения.
- [ ] `[APPS-06]` **luxdb** — клиент SQLite/Postgres: таблицы, запросы,
  редактируемая сетка (драйверы — в модуле приложения).
- [ ] `[APPS-07]` **luxk8s** — дашборд Kubernetes (как k9s) через
  `kubectl` exec.
- [ ] `[APPS-08]` **luxnotes** — markdown-заметки с поиском и превью.
- [ ] `[APPS-09]` **Игры** для демо: тетрис, змейка, 2048, сапёр, шахматы
  по SSH — витрина анимаций и ввода.
- [ ] `[APPS-10]` **luxchat** — чат по SSH для нескольких пользователей
  (витрина SSH-сервера).

### XVII.3. Правила для флагманов

- Каждая проблема, найденная в приложении, — задача в lux (не обход в
  приложении).
- Приложения обновляются на каждую новую версию lux в день релиза — это
  проверка, что релиз не ломает реальный код.
- У каждого — README с гифкой, установка через `go install` и бинарники.

**Готово, когда:** у трёх основных есть публичные релизы и реальные
пользователи; ни одно не содержит своих виджетов, которые должны быть в
lux.

## Часть XXI. Чего не делать никогда

1. **Не тянуть зависимости** в основной модуль. Три: `x/sys`, `x/term`,
   `uniseg`. Отдельные модули (SSH, WASM, luxvet, приложения) — свои
   зависимости можно, ядро не трогают.
2. **Не делать CSS**, селекторы, каскад, stylesheet-язык. Стили — Go-код
   и токены.
3. **Не делать retained-дерево, DOM, виртуальный DOM, React-хуки.**
   Immediate-mode — наша идентичность.
4. **Не клонировать lipgloss** (стилизацию строками) — у нас ячейки.
5. **Не GPU, не JS-рантайм** в основном модуле.
6. **Не terminfo-exec** и не `tput` — только пробинг.
7. **Не виджеты «для коллекции»** — у каждого есть сценарий из
   флагмана или cookbook.
8. **Не невоспроизводимые цифры** в README и статьях.
9. **Не ломать API после v1.0** без v2.
10. **Не жертвовать корректностью ради скорости** — ни одна оптимизация
    не стоит сломанного экрана.
11. **Не писать в терминал без согласия** (буфер обмена, уведомления,
    заголовок) — только по опции.

## Часть XXII. Как работать над каждой задачей

1. Взять следующий ID по годовому плану (часть XIX).
2. Прочитать код, который задача трогает, целиком. Понять поток.
3. Маленький кусок: одна фича или один баг за раз.
4. Сначала тест, который падает. Потом минимальный код.
5. Видимая фича — пример в студии/галерее, проверка вживую (ConPTY-харнесс
   или PTY, без управления рабочим столом пользователя).
6. Gate: gofmt; vet под windows/linux/darwin/freebsd; `go test -race ./...`;
   golangci-lint под windows/linux/darwin.
7. Review сделанного + мутационная проверка: сломать код руками — тест
   должен упасть. Исправить найденное.
8. Строка в CHANGELOG (по-английски), отдельный коммит с ID в сообщении
   (`feat(ui): add Slider [W-29]`), push.
9. Поставить `[x]` у пункта в этом файле.
10. Раз в квартал — пересмотреть план: что устарело, что добавить.

## Приложение D. Глоссарий

- **Ячейка (Cell)** — одна позиция на экране терминала: символ + стиль.
- **Графема** — то, что человек видит как один символ (может быть
  несколько кодовых точек: эмодзи, буква с акцентом).
- **Immediate-mode** — интерфейс заново описывается на каждом кадре
  функцией; виджеты не хранятся в дереве.
- **Пробинг** — вопросы терминалу при старте («что ты умеешь?») и
  разбор ответов.
- **Деградация (лестница)** — что показываем, если терминал не умеет
  лучшего варианта.
- **Токен** — именованное значение дизайна (`accent`, `space.2`), из
  которого строятся стили.
- **Golden-снимок** — сохранённый эталонный кадр, с которым сравнивается
  результат теста.
- **Soak** — долгий прогон для поиска утечек.
- **Мутационная проверка** — намеренно ломаем код и убеждаемся, что тесты
  это ловят.
- **Флагман** — настоящее приложение на lux, которое показывает и
  проверяет библиотеку.
- **Gate** — набор проверок, который обязан пройти перед коммитом.
