Mechanism (pinned by tests, traced to code):
  - state: Lines []string (no embedded newlines), Line/Offset caret,
    AnchorLine/AnchorOffset selection anchor, Wrap render.WrapMode,
    Scroll ScrollState, MaxBytes/UndoBytes bounds; zero value ready
  - EGC truth: every caret/anchor offset is forced to a grapheme
    boundary by normalize and kept there by insert/delete operations;
    boundary goldens run through the same textBoundary helper the
    fuzz invariants use; a combining mark typed after "!" appends to
    the same cluster ("scroll.!" + U+0301)
  - layout cache: buildLayout wraps a logical line into rows only when
    its recorded line bytes changed or its width/policy changed
    (invalidate/invalidateRange track a dirty range from the edit);
    a keystroke re-wraps the edited line, not the document; validateLayout
    pins that every row is a byte slice of its line between recorded
    starts; spliceRows/recountRows keep row counts and totals coherent
    after inserts/deletes
  - caret mapping: caretPosition maps (Line, Offset) to a wrapped row
    and cell; the caret at the end of a width-filling row flows to the
    next row's first cell; doc-end caret on a full last visual row
    paints no caret (known edge, not asserted, documented)
  - scroll: EnsureVisible keeps the caret row inside the viewport when
    focused; wheel and scroll keys move the viewport independently of
    the caret; positionAtPoint maps a click back through the layout to
    a boundary caret
  - history: snapshots coalesce per edit group, bounded by UndoBytes
    (trimHistory drops oldest); redo stack cleared on new edits;
    applyHistoryKey recognizes ctrl+z/y through RuneKey events
  - paste: sanitization normalizes \r\n and lone \r to \n, drops other
    control graphemes, splits into lines, and trims to the MaxBytes
    budget; "x\ny" pasted at (0,0) of ["ab","cd"] yields ["x","yab","cd"]
    (the suffix follows the last pasted line, VS Code semantics);
    an empty replacement still deletes the selection (regression)
  - first-frame caret: Context.focusPending lets the first focusable
    region act on focus before registration (caret reveal before the
    content limits are recorded), so a static app's only frame already
    paints the caret; Focus is committed on present as before
  - shortcuts: while the editor holds focus, ctrl+w/c/x/v arrive via
    Owner+ScopeFocused shortcuts registered in View; Esc needs a
    Priority ScopeApp shortcut because the focused area consumes plain
    keys as Input routing

Known limits (honest, not fixed this slice):
  - the layout cache is line-granular: editing a single huge line
    re-wraps that whole line per keystroke (~0.72 ms at 128 KiB);
    per-row incremental rewrap is future work, documented
  - a caret at the very end of a document whose last visual row is
    exactly full paints no caret cell (the flow-over cell would be
    outside the buffer); not asserted anywhere, left as an edge
  - golangci-lint: NOT RUN (not installed on this machine; go vet +
    gofmt ran instead)
