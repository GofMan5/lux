API (verified by test, not by inspection):
  - suspendTerminal(): true = the terminal was handed away cooked. Refuses
    (false, zero writes) on !opened, plain, or already-suspended; the
    leave is the exact sequences() Close would write for the same latch
    state (kitty pop before mode reset, title pop after); cooked restored
    via term.Restore with the OPEN-time state; errors inside the suspend
    are tolerated (the process is stopping regardless).
  - resumeTerminal(): nil = the terminal is raw again and the next Present
    is a full repaint. Nil no-op on !opened, plain, or !suspended. Error
    "terminal: resume without terminal input" keeps the latch SET and the
    baseline dropped. A MakeRaw failure returns the error, latch stays
    set, Present keeps refusing; a later successful resume recovers
    (enter written, latch cleared). Success always: suspended = false,
    previous = nil.
  - Present during suspension: nil error, zero bytes, previous untouched.
  - Close during suspension: leave written again (idempotent double-pop —
    the kitty/title stacks underflow-protect on xterm-family terminals;
    documented), latch cleared, later Present fails as on any closed
    backend.
  - deliverLifecycle: non-blocking send into b.events — a busy app drops
    the notice instead of wedging the watcher (the terminal transitions
    have already happened; the repaint does not depend on the event).
  - Run loop: Suspend/Resume ride the default applyEvent branch — Update
    + dirty + repaint on tick; no app.go changes; models written before
    the kinds existed treat them as ordinary updates.

Not claimed (doc truth, mirrored in README + CHANGELOG + COMPATIBILITY):
  - SIGTTOU: a background-write stop happens outside this watcher; the
    design targets foreground job control only.
  - Windows resume: console-close cleanup is best-effort — the OS still
    terminates the process in its ~5-second window.
  - real-terminal SIGTSTP/fg evidence: the unit tests pin the byte and
    state contracts on file streams; the actual PTY round trip is the
    stage-9 PTY lane (next slices).
  - signal watcher goroutine itself untested in this slice — its
    suspend/resume calls are the unit-tested methods; the PTY lane runs
    the watcher for real.
