## Truths written into the doc
- The recipe's worked example is a Stepper `[− 42 +]`: StepperState
  (zero value = 0, unbounded; Max > Min bounds; Step <= 0 reads as 1),
  StepperStyle (zero values inherit Normal), Apply(action Action), and
  Context.Stepper(id, canvas, bounds, state, style).
- THE DOC CANNOT ROT: the exact stepper code lives in
  ui/stepper_recipe_test.go (package ui) and runs under `go test ./ui/`.
  Editing one without the other fails the doc's own claim.
- Routing truths the doc states and the tests prove:
  * A press on a Scrollable-only region arrives as Scroll ON THE PRESS with
    region-local X — that is how one ID serves two halves (X==0 minus,
    X==W-1 plus, middle inert).
  * Key releases are inert (event.KeyEvent{Action: event.ActionRelease}).
  * Enter/Space are inert for the stepper: not an Activatable region, no
    commit semantics claimed.
  * Wheel up/left = +step, wheel down/right = −step; PageUp/PageDown = ×10.
  * action.X is region-local even inside clipped/scrolled regions.
  * Registering a duplicate ID during Begin..End panics on purpose.
- The doc's wiring snippet mirrors examples/widgets/main.go's real
  Update/View loop (Handle → switch action.Target → Apply; Begin/End with
  defer, draw through frame.Canvas).
- Testing ladder documented: (1) Apply table tests, (2) paint test with
  Begin/End + cell readback, (3) routing test via committed snapshot +
  Handle (press at absolute 12,1 → local X 8 → +1), (4) app-level
  interactive e2e (examples/widgets/main_test.go).
- Free-vs-owned table: framework owns hit-testing, focus/Tab/hover/capture,
  routing kinds, EGC clipping, release-commit geometry; the author owns
  Apply, draw, the shared layout truth, the not-claimed list.
- Not-claimed for the stepper: drag-seek (gauge's contract), digit typing
  (Input territory), float mode, repeat-on-hold, external spin buttons.

## Tests (ui/stepper_recipe_test.go, 5 functions)
- TestStepperApplyKeys: right ×2, left, PageDown ×10, key-release inert,
  Activate-kind inert. (Found and fixed a test-math bug during red phase:
  PageDown is +10 by the doc's convention, not −10.)
- TestStepperApplyBounds: Home/End clamp to Min/Max; step at Max is
  changed=false; Home on an unbounded stepper is inert (no Min/Max range).
- TestStepperApplyPointer: minus half −1, plus half +1, middle press inert,
  wheel up +1, mouse release inert, nil *StepperState inert.
- TestStepperPaint: 20×3 buffer, bounds X4 Y1 W9 H1, value 42 → exact row
  "    -  42   +" (read back cell-by-cell; no Buffer.Row helper exists).
- TestStepperRoutingEndToEnd: presented() snapshot + ctx.Handle: press
  (12,1) → {Target "stepper", Kind Scroll, X 8} → Apply → 1; KeyRight →
  Scroll → Apply → 2.
