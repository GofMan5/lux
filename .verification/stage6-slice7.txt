Provenance truth (research pass over tmux 3.3a→master sources — input.c,
tty-keys.c, tty.c, screen-write.c, options-table.c, CHANGES; GNU screen
ansi.c; kitty keyboard-protocol.rst; tcell v3 tscreen.go; bubbletea v2
tea.go; WezTerm docs — full quotes with line refs in the report that fed
this artifact, deleted before the commit; facts below are the ones that
survived cross-verification):
  - tmux's server-side pane parser (input.c) answers DA1 itself; the host
    terminal's real reply is consumed by tmux's client key parser
    (tty_keys_device_attributes, once-only) and NEVER reaches the pane.
    Exact DA1 bytes: "\x1b[?1;2c" (standard) / "\x1b[?1;2;4c"
    (--enable-sixel build). Identical in 3.3a and master.
  - GNU screen replies byte-identical "\x1b[?1;2c" (ansi.c L1045-1048):
    DA1 alone cannot distinguish tmux from screen or a legacy terminal —
    the DA1 witness is a "legacy-shaped replier" heuristic; harmless
    because the gate treats every multiplexer the same.
  - DA2: tmux "\x1b[>84;0;0c" (84='T'); screen "\x1b[>83;<version>;0c"
    (83='S'). tmux's 84 is a near-collision-free fingerprint: Windows
    Terminal 0, xterm 41, VTE 65, screen 83, WezTerm 123, kitty 1. Screen's
    83 is NOT used: the version parameter drifts between builds and 83 was
    never audited for exclusivity among real terminals, so screen stays
    environment-detected ($STY, screen* $TERM).
  - DECRPM timeline: <=3.3a drops ALL private DECRQM; 3.6 answers only
    12/2004/1004/1006/2031 and consumes the rest with no reply; 3.7+
    answers 1,3,6,7,12,25,47/1047/1049,1000,1002,1003,1004,1005,1006,
    2004,2026,2031 from pane state, unknown modes -> ";0$y". So 1016 and
    9001 get ";0$y" (rejected) on 3.7+, silence on <=3.6. Trap confirmed:
    "?6$p" is answered as DECOM (origin mode), not DECSDM — exactly the
    DECOM-as-DECSTBM-proxy lux already uses. screen: no DECRQM at all.
  - kitty keyboard in tmux: zero support through 3.8-dev (CHANGES has no
    kitty mention; the 'u' CSI table entry is RCP, so "CSI ? u" is
    silently dropped in ALL versions). screen drops it too. The kitty
    protocol spec's implementer list has neither.
  - DCS passthrough ("DCS tmux; ... ST"): default off, window/pane scope;
    outbound-only in practice — host replies either match tmux's own
    reply list (consumed for tmux's own detection, never forwarded) or
    are chopped under the default 10 ms escape-time and delivered to the
    pane as garbage META keys. No coherent host reply can reach a pane in
    stock tmux, so there is no byte-level "the host answered me directly"
    — the input gate is categorical, not a workaround for a solvable
    routing problem.
  - Environment witnesses: tmux sets $TMUX, $TMUX_PANE, TERM_PROGRAM=tmux,
    TERM from default-terminal; screen sets $STY, $WINDOW, TERM=screen.*.
    Env fails for ssh-from-inside-tmux (remote shell, local mux) and
    scrubbed-env wrappers — the DA2/DA1 report witnesses cover exactly
    those cases.
  - Market precedents: tcell v3 sends one fingerprint batch (DECRPM
    2048/1000/1006/9001, kitty ?u, XTVERSION >q, DA1 LAST as terminator,
    1 s bounded wait); bubbletea v2 probes DECRPM 2026+2027 behind a
    TERM/TERM_PROGRAM heuristic. Neither gates on $TMUX; neither attempts
    passthrough. lux's design (env pre-filter + DA2 fingerprint, one
    batch, bounded wait) matches the market pattern with a stricter
    verdict: gate input, trust output.

Honesty ledger:
  - the research pass could not build a SIXEL tmux, so ";4" DA1 replies
    are trusted from source reading, not from a live capture; the
    witness maps both shapes identically anyway.
  - "84 is claimed by no real host" is a characterization of the known
    emulator set, not a per-terminal audit; the false-positive cost is
    bounded by the gate itself (a colliding host would only lose input
    protocols it must first positively answer).
  - st's DA2 first parameter is suspected (from memory, not the research)
    to also be 83 — one more reason screen stays environment-detected;
    unaudited, documented as such in the code comment.
  - future tmux with native kitty would be wrongly gated until detection
    is taught — deliberate, documented in COMPATIBILITY.md.
  - the docker lane used golang:1.25-alpine (cached locally); CI pins go
    1.23.x and stable, so the matrix stays broader than this local run.
  - .research-mux/ (the research scratch: tmux/screen/tcell/bubbletea
    sources and the report) was deleted before the commit; the verified
