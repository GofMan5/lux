API (verified by test, not by inspection):
  - SparklineState{Values, Min, Max} is display-only: no region, no
    routing, no focus. Columns = min(bounds.W, len(Values)) painting the
    NEWEST values right-aligned (first = len(Values)-columns), so the
    series can be unbounded — the window is the cost. Min/Max pinned
    (Min < Max) set the axis; both zero (or inverted) auto-range per
    frame. Degenerate range (flat series or Min >= Max) -> every column
    the mid glyph "▄"; NaN -> floor ("▁"/empty column base); blank bounds
    or empty Values draw nothing. Each column fills bottom-up: full "█"
    cells, and the top cell is the 1..8-level cap glyph
    sparkGlyphs[ceil(remainder*8)-1]. H rows total; the level scale is
    shared across the whole bounds.
  - TreeRow{ID, Label, Depth} is the app's contribution per VISIBLE node:
    the app owns the expansion set (TreeState.Expanded map[string]bool,
    zero value nil and safe) and flattens lazily, so a million-node tree
    virtualizes exactly like a table — rowAt is called once per visible
    row. Apply(action, count, rowAt): release inert; count<=0 resets
    (Offset 0, Selected 0 — Expanded is NOT touched); Up/Down/Home/End/
    PageUp/PageDown/wheel ± max(rows/3,1) move the selection with clamp
    BEFORE the switch (Bounds.H defines the page size; H<=1 page keys
    still move by 1); MousePress selects Offset+Y (region-local); and
    Activate (Enter, Space, completed click) toggles Expanded[row.ID]:
    activated=true ALWAYS, changed=true ONLY when the entry flips (leaf
    rows activate without claiming change; a collapsed entry stays in the
    map as false). IsExpanded nil-receiver-safe. Drawing pools indents
    (treeIndents, two spaces per depth), draws Collapsed "+"/Expanded "-"
    markers for rows whose children exist — the marker decision is the
    APP's: the draw only sees the flattened rows, and tree_test's helper
    demonstrates the convention (a row is a branch when it has children
    in the source). Labels clip to the bounds with the app's width
    policy. The region is Focusable|Scrollable|Activatable, and drawing
    clamps the offset and calls ensureVisible (so keyboard selection
    never strays off-screen).
  - Tree contract note: KeyLeft/KeyRight are routed but INERT (collapse/
    expand-on-arrow is not claimed), and the widget deliberately follows
    the LIST semantics — wheel moves the selection, not the viewport.

keepTabVisible fix (ui/tabs.go, found live in the catalog):
  - The old visibility check compared the selected tab's CLIPPED slot end
    against the strip width, and a slot truncated to one cell by the right
    edge always fit: selecting the 4th tab of a 22-cell strip (labels
    table/form/motion/tree) left "tree" clipped to an invisible 1-cell
    slot while the strip reported it visible. The catalog paint test at
    Selected=3 failed exactly there — the e2e/paint pair caught a real
    widget bug, which is the point of stage 8.
  - Now visibility is measured against the WHOLE label width (sum of
    label widths + padding from Offset), the scan advances until the
    selected label fits fully or reaches the left edge, and it sums
    widths directly instead of building a tabLayout per step: one
    allocation and ~16% of BenchmarkTabsDraw gone. ui/tabs_test.go's
    keepTabVisible expectation was updated — it had pinned the buggy
    semantics (clipped tail "visible").
