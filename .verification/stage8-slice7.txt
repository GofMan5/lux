Stage 8, slice 7: window title with stack-based restore
Date: 2026-10-08
Machine: Windows amd64, i5-10400F, Go 1.25.5 (host), golang:1.25-alpine (docker)

WHAT
- lux.WithTitle(title string) Option; terminal.Title(title string) Option.
- Title written once via OSC 0 ("\x1b]0;<title>\a"), bracketed by the
  XTWINOPS title stack: CSI 22;0 t (push) rides the enter write, CSI 23;0 t
  (pop) rides the leave write on every exit path (Open-failure branch,
  Present-write failure path reuses the same leave assembly via writeSlot
  contract, Close, panic cleanup) — zero additional Write syscalls.
- sanitizeTitle strips C0 (<0x20), DEL (0x7f), and C1 (U+0080..U+009F)
  runes before any write: a BEL/ESC inside an OSC string would terminate it
  early and leak the rest as commands. Graphic runes (any script) pass;
  invalid UTF-8 passes as-is (cannot inject a control sequence). Runes are
  handled as runes, so multi-byte UTF-8 never corrupts.
- sequences(pixel, kitty, win32, unicodeCore bool, title string) (enter,
  leave string): the enter/leave latch assembly extracted from Open and
  Close into one pure table. Behavior-identical ordering: title push+set
  lead the enter; title pop closes the leave (after every mode reset).
  Kitty enter/leave order is now table-pinned (was only Open-inline).
- App wiring: config.title, defaultBackendOptions appends
  terminal.Title(settings.title) unconditionally (empty = inert no-op;
  plain/default builds stay byte-identical). Public Backend interface
  unchanged: custom adapters own their own title policy.
- b.title is opt-level state (like hyperlinkOpted), survives Close, so
  Open-after-Close re-pushes the title.
- Invariants pinned by tests: plain path (TERM=dumb + pipe) writes zero
  title bytes at Open/frame/Close; backend without title never emits
  titlePush/titlePop/OSC 0; pop only when configured; sanitized-only
  emission; no probe/parser/encoder/capability changes (negotiate,
  capability.Set, vtgrid, encoder all untouched).

DESIGN NOTES (decisions recorded for the audit trail)
- Stack (22;0/23;0) over query-and-restore (CSI 21 t reply is an OSC
  string that parses as keystrokes when misrouted — ambiguous, rejected)
  and over plain set-then-hope. Terminals without the stack ignore both
  operations: the title persists after exit there — documented in
  COMPATIBILITY.md matrix (ConPTY/ConHost), not silently mishandled.
- No capability gating: the stack has no detectable reply, so a gate
  would be a guess; the honest matrix is cheaper.
- OSC 0 (icon+window) over OSC 2 (window only): one sequence, both
  surfaces, and tmux propagates both.
- Title bytes: push(6)+OSC head(4)+title+BEL(1)+pop(6) — bounded by
  len(title)+17, once per Open, once per Close.
- not claimed: runtime retitling after Open, per-frame titles, OSC 1
  icon-only form, CSI 21 t query, title support in custom Backends.
