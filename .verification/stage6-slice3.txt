Doc-truth cross-check (every claim traced to code or spec first):
  - kitty encoder bits (kitty mouse.c encode_mouse_event_impl): SHIFT=4,
    ALT=8, CONTROL=16, MOTION=32, EXTRA=128, LEAVE=256; leave is
    256|32|mods in [256,316]; back/forward are 128/129 with 130/131
    reserved. The decode mirrors those exact numbers.
  - CSI 16 t replies CSI 6 ; height ; width t, height FIRST (xterm
    ctlseqs "CellSizeReport" and kitty screen.c agree) — parts[0] is
    height in parseCellSizeReport.
  - pixel coordinates are 0-based viewport pixels, no padding (kitty
    mouse.c reports the raw pointer position; cell_for_pos divides by
    the cell size), so floor division x/cellW is the truthful mapping
    and cell (0,0) is the first cell.
  - 1016 replaces the SGR *cell encoding* for the same event encoding:
    enterPixel omits ?1006 (1016 subsumes it), leavePixel symmetric
    (kitty mouse.c uses the one event encoder for both).
  - DECRPM status for 1016: 0 and 4 mean the mode cannot be set, so
    pixel reports would never arrive — featureFromStatus treats them as
    rejected, identical to the 2026 ladder.
  - the probe's early return now needs pixel != unknown; the grace
    break stays 25 ms behind the classic trio, so a terminal without a
    1016 answer costs only the grace (TestNegotiateKittyGrace silence).
  - resize re-query: deliverEvent writes cellSizeQuery under the write
    slot with mu released (no deadlock against Present/Close; a missed
    re-query is acceptable, the next resize asks again).
  - leave sentinel clears hover: X/Y=-1 miss every hit test in
    ui handleMouseLocked, and hover resets with zero visual churn.

Known limits (honesty):
  - Open-level pixel enter/leave writes are untested at byte level for
    the same tty-gating reason as slices 1-2 (Windows CI has no tty);
    Close-level restore and the enter failure branch are covered.
  - until the CSI 16 t reply lands (milliseconds after enter) pixel
    moves carry real pixels but X/Y = -1, which transiently clears
    hover; documented in COMPATIBILITY.md instead of papered over.
  - back/forward buttons: kitty is the reference; xterm's 1006 never
    sends them (its buttons 8/9 are wheel), and the cell decoder
    accepts 128/129 anyway — a future terminal sending them under 1006
    is decoded, which matches the "accept any SGR report" policy.
  - the docker Linux lane used golang:1.25-alpine (cached locally); CI
    pins go 1.23.x and stable, so the matrix stays broader than this
    local run.
