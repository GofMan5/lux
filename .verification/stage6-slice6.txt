Spec truth (double-verified: local copy of the Microsoft spec + a research
pass over tcell v3, charm x/input, WezTerm, and ConPTY captures; spec:
https://github.com/microsoft/terminal/blob/main/doc/specs/%234999%20-%20Improved%20keyboard%20handling%20in%20Conpty.md):
  - record CSI Vk;Sc;Uc;Kd;Cs;Rc _ : virtual key, scan code, Unicode
    translation, key-down, control-key state, repeat count; DECIMAL
    parameters; defaults 0,0,0,0,0 and REPEAT=1; ";;" skips a field;
    the spec's own examples use truncated forms.
  - enable/disable: CSI ? 9001 h / l — a plain DEC private mode, literal
    set/reset, NO push/pop stack. ConPTY itself always enables 9001 at
    spawn; the enable is idempotent and the leave matches the session.
  - ConPTY serializes only KEY_EVENT_RECORDs; VK_PACKET/IME chars bypass
    the records and arrive as plain characters.
  - ControlKeyState bits: RIGHT_ALT 0x1, LEFT_ALT 0x2, RIGHT_CTRL 0x4,
    LEFT_CTRL 0x8, SHIFT 0x10, NUMLOCK_ON 0x20, SCROLLLOCK_ON 0x40,
    CAPSLOCK_ON 0x80, ENHANCED_KEY 0x100.
  - Support matrix: Windows Terminal YES, ConPTY ConHost YES, WezTerm YES
    (default-on for Windows since 20220624-141144), mintty NO (kitty
    instead), foot NO (kitty instead). Silence => legacy path, honestly.

Decode semantics (parser.go, ~200 lines + tests):
  - printable Uc (incl. space, unicode.IsPrint) is the text path: KeyRune
    with the rune verbatim and modifiers intact (Shift+A reads 'A' +
    ModShift, matching the kitty arm).
  - AltGr truth: the real chord is LEFT_CTRL|RIGHT_ALT = 0x9, so
    cs&0x9==0x9 on a printable strips ModCtrl|ModAlt — a Polish 'ą' on
    AltGr+A is a plain rune; genuine Ctrl+Alt (0xA) stays a combo. (The
    research report's "AltGr = 0xA" line is self-contradictory: 0xA is
    LCtrl|LAlt — the spec's own Ctrl+Alt example — and is correctly NOT
    stripped.)
  - win32Mods: ctrl = cs&0xC (BOTH ctrl keys), alt = cs&0x3, shift 0x10,
    caps 0x80, num 0x20; SCROLLLOCK_ON (0x40) and ENHANCED_KEY (0x100)
    deliberately dropped (documented in the code comment). NOTE: an
    earlier draft used cs&0x5 (RIGHT_ALT|RIGHT_CTRL!) — missed LEFT_CTRL
    entirely and read RIGHT_ALT as ctrl; caught by the test run before
    anything landed.
  - Uc zero/control => virtual-key path: letters, digits, F1-F24,
    navigation cluster, Backspace/Tab/Enter/Escape/Pause/CapsLock/
    PrintScreen/Insert/Delete/Menu, numpad operators, volume/media keys.
  - modifier bookends and other unmapped VKs (VK_SHIFT family, Win keys,
    bare numpad digits with Uc==0): well-formed records decode as
    KeyUnknown CARRYING the record's honest action/repeat/mod — a Ctrl-up
    bookend reads as a release, never a phantom press (parity with the
    kitty arm's unknown-modifier handling). Malformed records (>6 params,
    non-digit, signed, Kd outside {0,1}, rc>0xFFFF) return ok=false and
    fall through to the EXISTING legacy unknown-key fallback.
  - Shift+Tab normalizes to BackTab (kitty arm + legacy CSI Z parity).
  - the scan code is parsed for grammar and then ignored.
  - press coalesces Repeat = max(rc,1); kd=0 => ActionRelease, Repeat 0.
    Releases ride the same default filtering / WithKeyReleases(true)
    delivery as the kitty path.

Charm deviations (deliberate, documented in COMPATIBILITY.md): charm
requires exactly six parameters — lux accepts <=6 with per-parameter
defaults because the spec's own examples are truncated; charm reads any
non-1 key-down as release — lux rejects Kd outside {0,1} as malformed
(honesty over guessing).

Known limits (honesty):
  - decode tests are table tests; the full Open->probe->record path on a
    real ConPTY/WT/WezTerm console is stage-9/10 territory (no live
    terminal matrix yet).
  - the win32 probe verdict is not exercised end-to-end through a real
    Windows console — the negotiation tests are pipe-based (Linux lane).
  - ConPTY always emits ?9001h itself at spawn; lux's enable is
    idempotent and the leave is unconditional on the latched path, so a
    session that started cannot exit with the mode set — but the
    interaction "ConPTY set it, lux never latched it, other processes
    depend on it" is out of scope: the leave only fires when lux's own
    enable fired.
  - the docker Linux lane used golang:1.25-alpine (cached locally); CI
    pins go 1.23.x and stable, so the matrix stays broader than this
    local run.
  - .research-win32-input/ (the research scratch: spec copy, WezTerm
    sources, report) was deleted before the commit; the verified facts
    live in this artifact, the code comments, and the spec URL.
